阶段 0 · 第 0.1 节

算法与时间复杂度

阶段 0 · 基础备查
这一节要解决什么？

机器人要在 n 个候选位置里找一个编号，数据翻倍时需要多少次检查？时间复杂度描述输入规模增大时，主要操作数量怎样增长。

一、先理解做法

顺序查找最坏可能看 n 项；有序数据的二分查找每次排除约一半，最坏比较次数随 log n 增长。O 记号描述渐近上界，实际耗时还受常数、数据与实现影响。

怎样理解时间复杂度？

n 表示输入规模，例如数组长度。复杂度描述规模增大时操作次数的增长趋势；它不是秒数。O 表示渐近上界，应结合具体算法和输入条件理解。

复杂度常见场景规模增大时
O(1)按下标读取数组次数不随 n 增长
O(log n)二分查找每步排除一半
O(n)遍历数组数据翻倍，次数约翻倍
O(n log n)归并排序约 log n 层，每层处理 n 项
O(n²)两层各遍历 n 次数据翻倍，次数约变四倍
O(2ⁿ)枚举 n 个元素的所有子集每增加一个元素，候选数翻倍
O(n!)枚举 n 个不同元素的所有排列增长非常快

例如 n=8 时，n、n²、2ⁿ 分别为 8、64、256；二分最坏比较次数约为 4。具体次数与实现有关，表格用于理解增长趋势。

如何自己计算？

  1. 先找出输入规模 n 和最常执行的操作。
  2. 顺序执行的代码次数相加；嵌套循环内外次数相乘，例如 n 次中每次再遍历 n 次得到 n²。
  3. 循环变量每次减半或翻倍，通常有 O(log n) 次；递归则要同时看每层工作量和层数。
  4. 忽略与 n 无关的常数和低阶项：3n²+5n+2 的渐近上界为 O(n²)。

不要见到两层循环就断定是 O(n²)：滑动窗口的两个指针各最多前进 n 次，因此总时间是 O(n)。均摊 O(1) 是多次操作的平均上界，不保证每次都一样快。空间复杂度要计算额外数组、队列和递归栈；输入是否计入需说明。

小练习：一次循环执行 n 次，循环内再执行固定 10 次，复杂度是什么？答案：O(n)，因为 10 是常数。

三、C++ 实现

先读参数与返回值，再逐行对照上面的状态变化。标准容器写法假定已引入相应头文件并使用 std 命名空间；结构定义和片段按上下文放入程序。

int linearSearch(const vector<int>& nums, int target) {
    for (int i = 0; i < (int)nums.size(); ++i) {
        if (nums[i] == target) return i;
    }
    return -1;
}

四、复杂度与适用条件

一次随机下标访问通常 O(1)，顺序遍历 O(n)，二分 O(log n)，两层各运行 n 次的循环 O(n²)。空间复杂度需要看额外存储，不等同于输入本身大小。

五、独立练习

分别估计遍历 100 个元素、以及两层循环各遍历 100 次时的循环体最多执行次数。

查看提示与易错点

分清固定次数和随 n 增长的次数；复杂度不等于具体运行秒数。
