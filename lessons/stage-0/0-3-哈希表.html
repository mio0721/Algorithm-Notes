阶段 0 · 第 0.3 课

哈希表 unordered_map 与 unordered_set

阶段 0 · 基础备查

一、简单例子

一串设备编号不断到来，我们想快速知道“这个编号来过没有”，也可能需要记录每个编号对应的信息。哈希表像按编号查档案的索引。

先看一个小例子

先收到42，记录“42出现过”；再收到17也记录；又收到42时，直接查到已有记录，不必把所有旧编号再遍历一遍。

二、解释与思考

哈希表先用一个计算规则，把键转换成存放位置的线索，查找时再按同样的规则定位，通常不用逐条翻找。不同的键可能落到同一处，这叫冲突，容器还要继续比较键来分清它们。因此查找、插入通常很快，但并非任何情况下都只需一步，也不保证按大小顺序遍历。

  1. 明确只需要判断存在，还是需要保存编号对应的值。
  2. 按键查找已有记录。
  3. 需要时插入新键或更新它的值。

四、深入理解

想快速查询某个节点是否访问过，可以用集合记录；需要从节点编号找到对应信息时，可以使用键值映射。

把刚才的动作说准确

unordered_map 用键找到值；find 查找后必须与 end 比较，确认存在再用迭代器。unordered_set 只存键。下标运算符 map[key] 在键缺失时会插入默认值。

什么时候用哈希表？

只判断是否出现过，用集合；需要保存“值 → 下标”，用映射。例如遍历 [4,7,9] 时记录 4→0，再查找补数。重复键会更新对应值；不要假设无序容器按插入顺序遍历。

平均 $O(1)$ 依赖哈希质量，最坏可退化到 $O(n)$。C++ 使用 find 检查是否存在；Python 可用 in 或 get。

五、复杂度与易错点

需要多少工作与存储？

合理哈希条件下查找、插入平均 $O(1)$，最坏 $O(n)$；无序容器不保证遍历顺序。

容易错在哪里具体反例怎样改
用下标访问只想查询的键C++中的mp[99]可能插入默认值不想插入时用find或count。
依赖哈希表遍历顺序插入顺序不同，输出顺序可能变化需要有序结果就另外排序，不能把内部顺序当合同。
再检查一个容易忽视的条件

find 返回迭代器；it->first 是键，it->second 是值，缺失时不能解引用 end()。
