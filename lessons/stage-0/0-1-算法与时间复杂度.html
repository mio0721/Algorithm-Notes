阶段 0 · 第 0.1 课

算法与时间复杂度

阶段 0 · 基础备查

一、简单例子

书架上有100本书，找一本书可以逐本看，也可以利用书名顺序不断排除一半。我们想比较的是工作量怎样增长，而不是某台电脑恰好用了几毫秒。

先看一个小例子

逐本查看100本书，最坏要看100次；每次排除一半，只需大约7次。书变成1000本时，前者可能看1000次，后者大约10次。

二、解释与思考

算法就是解决问题的一套明确步骤。比较两种算法时，可以先数它们要做多少次关键动作，再看数据增多后次数怎样增长：逐个检查通常随数据量一起增长，每次排除一半则增长得慢得多。时间复杂度描述这种增长趋势，不是程序实际运行的秒数；空间复杂度则关注需要多少存储。

  1. 先数一次核心动作，例如比较一次书名。
  2. 观察数据变多后，动作次数是保持不变、翻倍，还是增长得更快。
  3. 用增长类型描述方法，最后再认识它的复杂度符号。
操作前先猜一猜

把数据量翻倍，逐本查找和两两比较的工作量会各增加多少？

四、深入理解

机器人要在 n 个候选位置里找一个编号，数据翻倍时需要多少次检查？时间复杂度描述输入规模增大时，主要操作数量怎样增长。

把刚才的动作说准确

顺序查找最坏可能看 n 项；有序数据的二分查找每次排除约一半，最坏比较次数随 $\log n$ 增长。O 记号描述渐近上界，实际耗时还受常数、数据与实现影响。

怎样理解时间复杂度？

n 表示输入规模，例如数组长度。复杂度描述规模增大时操作次数的增长趋势；它不是秒数。O 表示渐近上界，应结合具体算法和输入条件理解。

复杂度常见场景规模增大时
$O(1)$按下标读取数组次数不随 n 增长
$O(\log n)$二分查找每步排除一半
$O(n)$遍历数组数据翻倍，次数约翻倍
$O(n \log n)$归并排序约 $\log n$ 层，每层处理 n 项
$O(n^2)$两层各遍历 n 次数据翻倍，次数约变四倍
$O(2^n)$枚举 n 个元素的所有子集每增加一个元素，候选数翻倍
$O(n!)$枚举 n 个不同元素的所有排列增长非常快

例如 n=8 时，n、$n^2$、$2^n$ 分别为 8、64、256；二分最坏比较次数约为 4。具体次数与实现有关，表格用于理解增长趋势。

如何自己计算？

  1. 先找出输入规模 n 和最常执行的操作。
  2. 顺序执行的代码次数相加；嵌套循环内外次数相乘，例如 n 次中每次再遍历 n 次得到 $n^2$。
  3. 循环变量每次减半或翻倍，通常有 $O(\log n)$ 次；递归则要同时看每层工作量和层数。
  4. 忽略与 n 无关的常数和低阶项：$3n^2+5n+2$ 的渐近上界为 $O(n^2)$。

不要见到两层循环就断定是 $O(n^2)$：滑动窗口的两个指针各最多前进 n 次，因此总时间是 $O(n)$。均摊 $O(1)$ 是多次操作的平均上界，不保证每次都一样快。空间复杂度要计算额外数组、队列和递归栈；输入是否计入需说明。

小练习：一次循环执行 n 次，循环内再执行固定 10 次，复杂度是什么？答案：$O(n)$，因为 10 是常数。

五、复杂度与易错点

需要多少工作与存储？

一次随机下标访问通常 $O(1)$，顺序遍历 $O(n)$，二分 $O(\log n)$，两层各运行 n 次的循环 $O(n^2)$。空间复杂度需要看额外存储，不等同于输入本身大小。

容易错在哪里具体反例怎样改
看见两层循环就认定很慢内层只固定执行3次，外层走过每个元素先数总次数，固定3次不会变成平方增长。
把复杂度当成秒数两台电脑运行同一个方法，用时不同复杂度比较增长趋势，实际用时还受实现和硬件影响。
再检查一个容易忽视的条件

分清固定次数和随 n 增长的次数；复杂度不等于具体运行秒数。
