堆与优先队列

阶段 0 · 基础备查

一、简单例子

多个任务随时加入，但每次都想先处理优先级最高的一个。我们不一定需要把全部任务排好，只要快速拿到当前最重要的任务。

先看一个小例子

待处理代价是 [8,3,6]，先处理3；随后加入1，下一次应该先处理1，而不是机械地接着处理6。

二、解释与思考

堆只维护一种局部关系：以最小堆为例，每个父节点都不大于自己的孩子，所以最小值一定在顶部。加入新元素或移走堆顶后，只需沿树的一条分支调整，就能恢复这个关系。优先队列利用堆反复取出当前最优先的元素，但堆内部的所有元素并没有完整排好序。

  1. 把任务和优先级一起加入堆。
  2. 每次读取堆顶。
  3. 移除已处理任务，堆会重新保证顶端最优。
操作前先猜一猜

堆顶是最小值，是否意味着容器里其余元素也完全有序？

三、操作示意，观察过程

这是一个固定例子。先猜测下一步，再点击按钮；高亮表示当前关注的元素或状态。

四、深入理解

救援队需要优先处理代价最小的待办任务，而任务会持续加入：优先队列可以在动态变化中取出最高优先级元素。

把刚才的动作说准确

C++ priority_queue 默认 top 为最大值；使用 greater<int> 可以得到最小值优先的队列。先 top 读取再 pop 删除，空队列不可读取。

堆和排序的区别

最小堆只保证堆顶是最小值，不保证其他位置完全有序。每次弹出后堆会调整。Python 的 heapq 默认最小堆；C++ priority_queue 默认最大堆。元素优先级相同时，如需稳定顺序应增加明确的次序字段。

五、复杂度与易错点

需要多少工作与存储？

对常见堆实现，插入和弹出 $O(\log n)$，读取堆顶 $O(1)$，空间 $O(n)$。堆只保证堆顶满足优先级，不保证容器内部完全有序。

容易错在哪里具体反例怎样改
默认堆方向搞反C++默认priority_queue先弹出最大值求最小值需要greater；Python heapq默认最小堆。
以为遍历堆就是排序结果内部数组只保证局部父子关系需要完整有序输出就连续弹出，或使用排序。
再检查一个容易忽视的条件

模板中 greater<int> 对应最小值优先；Dijkstra 后续会用优先队列管理候选节点。
